# Живая диагностика камер Sea Lion 07 через ADB

Этот сборщик нужен для синхронного сравнения изображения штатных камер с
событиями `CamX`, `AVMCamera`, `SENSORLOCK`, `CameraDiagMask`, `MAX96712` и
`SerDes`.

Скрипт работает только на чтение. Он не очищает `logcat`, не меняет Android
settings, не перезапускает приложения или сервисы, не отправляет Binder-команды,
не устанавливает APK и не перезагружает автомобиль.

## Перед началом

- Автомобиль должен стоять на месте в режиме `P`.
- Mac должен быть подключён к автомобилю через ADB.
- Не проводите тест во время движения.
- Уберите из поля камер людей и чувствительные данные, если архив планируется
  передавать кому-либо: сборщик сохраняет снимки центрального экрана.

Проверьте соединение:

```bash
adb connect 192.168.0.216:5555
adb devices -l
```

В списке автомобиль должен иметь состояние `device`. Наличие выключенного
эмулятора не мешает, потому что автомобиль будет указан явно через `--serial`.

## Запуск

```bash
cd /Users/vyacheslavrud/Desktop/Projects/BYDMate
chmod +x scripts/collect-byd-camera-live.sh
./scripts/collect-byd-camera-live.sh --serial 192.168.0.216:5555
```

Скрипт покажет данные найденного устройства. Проверьте, что это
`DiLink5.0 For BYD AUTO`, введите:

```text
LIVE
```

## Как выполнять шаги

Для каждого шага сначала прочитайте требуемое действие. Затем:

1. Нажмите `Enter` на Mac.
2. Сразу переключите центральный экран в указанный режим.
3. Ничего не нажимайте следующие 10 секунд.
4. Дождитесь сообщения `snapshot`.

Последовательно будут записаны:

1. обычный экран DiLink при закрытом приложении камер;
2. начальный полный обзор 360°;
3. передняя камера;
4. задняя камера;
5. левая камера;
6. правая камера;
7. повторный полный обзор 360°.

Начальный и финальный обзор нужны, чтобы увидеть, меняется ли состояние общего
потока после переключения отдельных видов.

## Результат

По умолчанию на рабочем столе появятся:

```text
BYD-Camera-Live-YYYYMMDD_HHMMSS/
BYD-Camera-Live-YYYYMMDD_HHMMSS.tar.gz
```

Передайте для анализа файл `.tar.gz`. Не публикуйте архив и не добавляйте его в
Git: в нём могут находиться изображение окружающей обстановки, номера автомобилей,
текущий экран DiLink и runtime metadata.

Основные данные внутри архива:

- `events.tsv` — временные границы каждого режима;
- `continuous/logcat-full.txt` — полный журнал за время теста;
- `continuous/logcat-camera-relevant.txt` — camera-specific события;
- `snapshots/*/centre-screen.png` — видимый результат каждого режима;
- `snapshots/*/dumpsys-media-camera.txt` — состояние Android camera service;
- `capture-errors.log` — команды, которые прошивка не разрешила выполнить.

Снимки показывают уже отрисованный экран DiLink. Скрипт не извлекает необработанные
буферы `pano_h` и не читает `/dev/cam_power_supervise`, поскольку ADB-пользователь
`shell` не имеет прямого доступа к этим данным.

Если архив не создался, сохраните всю папку и сначала передайте `README.txt`,
`events.tsv` и `capture-errors.log`.
